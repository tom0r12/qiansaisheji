# 150 MHz 功能模式约束核查

评测条件为官方 SCC40NLL VHSC40 RVT TT 1.1 V、25°C 及相同 SRAM 工艺角，周期 6.666666667 ns。这是布局前理想时钟工程估计，不能称为布线后签核。

## 现有真实违例

原生 12 位输出版整机综合的最差 setup 为 -0.90802526 ns，主要终点位于 E203 ITCM 命令缓冲控制。该路径不增加 false path 或多周期例外；通过同一逻辑网表的增量映射、单元选择及 CPU 层次边界优化修复，随后做等价检查。

## 导出时钟分类

`qingyu_e203_soc_top.v:338` 明确 `assign loader_clk=qingyu_bus_clk`。原脚本对所有输出统一施加数据输出延迟，产生 `loader_clk` 的 -0.020 ns hold 违例。修订仅删除该时钟输出的数据延迟，并在此端口定义来源为原 `core_clk` 的 1:1 导出时钟。所有数据输出的 1 ns 最大延迟、0 ns 最小延迟不变，150 MHz 周期和不确定度不放宽。

## 原有 PWM 同步器异步入口

官方 `apb_adv_timer/input_stage.v:41–52` 包含 `r_ls_clk_sync[2:0]`，每个定时器执行 `r_ls_clk_sync <= {r_ls_clk_sync[1:0], ls_clk_i}`；只有同步后的第 1、2 位用于边沿检测。四个定时器均连接 `low_speed_clk_i`。

因此仅对 `lfextclk` 到四个既有同步器第 0 级 D 引脚设置异步入口例外，脚本精确检查目标数量为 4，并保存匹配的全部引脚及例外前路径报告。第 0→1、1→2 级仍正常进行 setup/hold 检查。没有对 CPU、加速器、共享 SRAM、总线或任意整个时钟组增加例外。

## 固定模式与证据

三路 debug strap 为 111，与原任务 TB 和板级默认上拉说明一致；在增量优化前施加，与之前报告阶段的功能模式相同。继承模式前 setup/hold、修订前约束、修订后路径、SDC、网表、宏清单、面积逐叶分解和源码身份分别保留。最终是否通过仍以实际工具结果为准。

## 后续发现与修复

第一轮增量映射的 setup 为 0.000 ns，但保持裕量仍为 -0.14896035 ns。真实路径为计算核心 `r_pending_value_q_reg` 到 `r_memory/stripe[0].g128.macro_ram/D`：数据到达约 0.16121438 ns，SRAM hold 约 0.29017472 ns，加上 0.020 ns 不确定度，要求约 0.31017473 ns。该数据路径不得设为 false path；新一轮综合执行独立 hold-only 映射修复。

同时，`check_timing` 指出加速器错误处理存在组合反馈：formatter ready -> 输出身份错误判断 -> soft_abort -> 写入 ready -> formatter ready。新候选仅把输出身份检查改为对已呈现的 valid 数据立即检查，与 ready 解耦；错误不会等到传输时才发现。原版冻结源码保留。12 项正常任务逐周期不变，另外两项全 SoC 错误注入覆盖 ready=1 和 ready=0，均完整排空在途事务且保持完成标志失效。需以新候选综合报告确认组合环和真实 hold 违例均消除，不能沿用前一网表的零 setup 结论。
