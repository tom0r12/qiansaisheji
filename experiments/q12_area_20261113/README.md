# Q12 保周期面积优化（2026-11-13）

## 修改范围

首版 `rtl/q12_task4.sv` 仅替换输出 `requantize` 组合函数。用有符号算术右移、guard/sticky 舍入和 13 位饱和加一，替代绝对值、宽掩码、宽比较和正负号恢复。保留所有 32 位输入、全部 8 位 shift 的原行为，包括 shift ≥ 32 返回零、负数 ties-to-even 和饱和边界。

本轮选择第二版 `variants/data_hold/q12_task4.sv`。在首版基础上只删除 burst 数据/地址以及待提交 bias/shift 数据的两处清零循环，共 2133 位数据不再清零；有效位和控制状态的复位全部保留。每一段数据在使用前仍须完整写入。没有减少寄存器容量、流水级、握手、乘累加阵列、精度或 SRAM 宏数量，也没有修改官方下游总线或共享 SRAM 入口。

`checks/data_hold_source_audit.json` 确认第二版与首版之间仅有这两处删除，舍入函数与已证明版本相同。`checks/q12_data_init_check.sv` 是非侵入 bind 检查器，不初始化 DUT 数据；12 个任务共检查 6144 次完整 burst 和 3072 次 metadata 读取前初始化。

## 面积与功耗口径

队友 HANDOFF 明确写明 0.48 mm² 是预算（0.45–0.52），尚未出具最终新增面积。局部面积下降不能直接视为整机下降 71%，也不能从预算减去局部差值后宣称得到实测整机面积。本轮已核对 1276 个标准单元的 Liberty area 与 LEF 微米尺寸乘积一致；两种私有宏也分别匹配 LEF，宏尺寸合计 135202.6782 µm²，与映射 DB 的浮点累计相符。

第二版完整 SoC 已完成综合，新增面积为 **0.468646862835 mm²**；核心组 setup 最差 **−0.53817463 ns**，因此尚未通过 150 MHz 时序。新解码候选正在复测准备中，详见 `PROGRESS.md`。同版活动功耗尚未出具。6.3 µJ 是每任务能耗目标，不是功率单位，不得套用旧版本功耗。基线 NP3 loader 对题面接口的合规待确认项仍继承为 OPEN，本次没有扩大接口。

## 复跑

本地 Linux/WSL：

```sh
python3 experiments/q12_area_20261113/run_checks.py
```

需要已有 Yosys 和 Verilator。验证日志和源码哈希写入 `checks/result.json`。初次尝试在负饱和边界发现的反例保留于 `checks/quant_counterexample.log`；当前版本使用严格 `< -4096` 比较，并已重新通过全部等价检查。

服务器工程包由 `server/package_server.py`、`server/package_replay.py`、`server/package_core.py` 生成，仅含工程源文件/启动脚本，不含 PDK、凭据或任务原始数据。依次对应单路综合、12 任务回归、完整核心综合。已经执行过的包不要重复启动；先读状态：

```sh
sh ~/Desktop/qt
```

启动脚本会校验上传 ZIP 哈希，在新的 `/tmp` 子目录运行，记录日志并与队友正在运行的整机综合隔离。每个综合进程有时间上限；不杀死原有任务。`/tmp` 结果不是长期归档，后续应把允许保存的小型报告保存在持久目录。

整机第二版评测包由 `server/package_full.py` 构造。它要求原评测包哈希完全匹配且第二版 12 任务已通过，在新的目录中仅替换计算核心文件，另写 derived identity；复制的冻结清单只用于来源追溯，不冒充新候选校验结果。当前启动情况见 `PROGRESS.md`。

没有将实验替换冻结候选。实验代码和已有检查证据已推送独立分支 `q12-area-optimization-20261113`；后续服务器结果按源码哈希记录，不能把已启动的作业当作通过。
