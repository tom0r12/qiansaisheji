# opt14_ybank2 输出缓存优化候选

本候选从 `opt13_row8` 的八行、十六通道计算核心派生。改动仅在 `rtl/qingyu_accel.sv`，其他 RTL 和固件保持与该基线一致。输入与权重格式、48 位累加、舍入与饱和规则、寄存器地址和输出字序不变。

## 改动及依据

原来的两个输出槽共用八个 128×16 单端口 SRAM 宏。每个宏只使用 32 个字；每次存储占用全部八个宏，阻止流式读出。八行的一批结果需要 16 个存储周期和 64 个流式读取周期，这两类访问不能重叠。

本候选为每个槽分配两个独占的 128×16 宏，总数从八个减至四个。每周期存储一对 INT16 结果；写一个槽时，可以同步读取另一个槽。每个宏使用 64 个字。八行的存储耗时为 64 周期，可与下一组的 64 次乘加及流水开销重叠。实际吞吐收益取决于输出消费速率与系统总线等待，必须以同条件仿真测量。

| 项目 | opt13_row8 | opt14_ybank2 |
|---|---:|---:|
| 输出 SRAM 宏数量 | 8 | 4 |
| 输出 SRAM 分配容量 | 2048 字节 | 1024 字节 |
| 有效输出槽容量合计 | 512 字节 | 512 字节 |
| 每周期存储结果数 | 8 | 2 |
| 活跃 INT16 舍入饱和表达式数量 | 8 | 2 |
| 不同槽读写同时进行 | 否 | 是 |

源结构上的宏数量和表达式数量不等于综合面积或功耗结论。四个宏的减少是确定的结构变化；门级单元数量、时序与功耗仍需指定工艺库实测。

## 地址与所有权

每槽保存最多八行、每行十六个 INT16 结果，即 64 个打包的 32 位字。

- SRAM 宏索引：`2 * slot + lane[0]`。
- SRAM 宏地址：`{row_within_batch[2:0], lane[3:1]}`，范围 0 到 63。
- 流式读取字索引：`fetch_index[5:0]`，同时读出该槽的两个宏。
- MMIO 读回仍为 `0x7000` / `0x7200`，每槽字数由状态寄存器返回。
- 槽在最后一个有效字写入后才置为 ready，读取完成并 release 后才允许重新存储。
- 最后不足八行的批次仅存储有效行；99 行任务的尾批次为三行、24 个打包字。

## 验证与限制

本候选沿用 opt13 的生产配置限制：`LANES=16`、`K=64`，启用 `OUT16`、`DOUBLE_BUFFER`、`PIPE_MAC`、`STREAM_MAC`。正常生产流同时启用 `READ_AHEAD`、`WEIGHT_STREAM` 和 `QINGYU_BLOCK_COPY`。

Icarus Verilog 已完成生产配置编译，零编译错误；现有数组组合敏感性提示保留在编译日志中。独立整数参考回归由项目新增的便携测试入口负责，结果应以该入口生成的 JSON 和日志为准。

2026-11-11 的第一组扩大回归中，opt12、opt13、opt14 各检查 20592 个结果并全部通过。测试覆盖 99 行尾批次、随机输出与 ICB 背压、每批首末字 MMIO 读回、满槽软复位、计算中硬复位和使用驻留权重重新启动。

在不额外插入消费暂停的同条件组件测试中，99×64 输入乘 64×16 权重的一次计算，`compute_cycles` 为 opt13 的 1037 周期、opt14 的 927 周期，13 次均相同，减少 10.61%。opt13 的存储/流读取重叠为零；opt14 在整轮测试中记录 9425 个重叠周期。对应证据为 `build/candidate_checks/20261111T115813962007Z/result.json`。这些是合成工程向量与行为 SRAM 下的组件结果，不能乘十六直接当作完整 E203 任务耗时。

在 `qingyu` 目录执行以下命令，可生成隔离的新一轮结果：

```text
python scripts/run_candidate_checks.py --candidate experiments/h1500v/opt13_row8/rtl --candidate experiments/h1500v/opt14_ybank2/rtl --cases 12
python scripts/run_candidate_checks.py --candidate experiments/h1500v/opt13_row8/rtl --candidate experiments/h1500v/opt14_ybank2/rtl --cases 12 --fast-consumer
```

尚未取得本候选的官方模型精度、完整 E203 端到端计时、厂家 SRAM 仿真、综合、Formality、150 MHz 时序或活动标注功耗结果。不能将 opt13 的已有服务器指标归给本候选，也不能仅凭内核测试宣称正式提交验收完成。

服务器打包脚本需要按本候选重新生成，不能直接运行 opt13 的硬编码打包入口。源结构私有 SRAM 数量应为 16 个 1024×16、37 个 128×16（其中 32 个权重、4 个输出、1 个元数据）；任何综合合并都须解释并记录实际宏数量。

时序复核需重点关注两个舍入饱和单元前的选择逻辑：每个单元现在从更多 shadow accumulator 中取值，组合选择深度可能增加。若 150 MHz 裕量不足，应先评估该路径，而不能以宏数量减少推断时序必然改善。
