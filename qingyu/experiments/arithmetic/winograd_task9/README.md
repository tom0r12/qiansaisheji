# Nine-row compute candidate

This independent revision uses 9 rows × 16 paired lanes while retaining the 32-bit prefetch8 interface and its two load/compute state machines. The module and RTL filename deliberately remain `winograd_int8_task8` for engine filelist substitution; the physical instance count is **144 paired lanes**, not 128. The frozen prefetch8 directory is unchanged.

Nine rows match the four-byte output bottleneck more economically than sixteen rows. Each full group emits 36 words while paired compute takes at least 35 cycles. With a bounded output snapshot, the per-tile schedule can approach 35 initial cycles plus 396 output cycles. Sixteen rows also face this same output bound, but require substantially more X storage and paired lanes. This is a scheduling rationale, not an area, energy or 150 MHz claim.

X still accepts exactly 1,600 words from the existing two-row adapter. The last 32 words contain row 98 in the low half and a canonical zero dummy row 99 in the high half. The high half is ignored for storage, factors and compute; it does not create a 100th row. All 99 real rows map to `bank=row%9`, `address=(row/9)*32+kpair`. The hardware implements this with bounded low-bank/group counters and a carry at the wrap, not a divider. Bank 8's high companion wraps to bank 0 at the next group address. Every bank stores 11 real rows, or 352 of its 1,024 words.

Computation covers 11 groups of 9 rows exactly, with no padded compute lanes. The R cache supplies nine factors during the first nine DOT cycles. A 3,510-bit raw/factor/context snapshot retains results during output; this is 389 more bits than prefetch8. Output word addresses use `group*36 + local_row*4 + word`, preserving the exact original tile-major byte stream. W remains sixteen single-port 128×16 banks with four logical slots and three bounded 256-bit write bursts. Metadata arbitration and slot retirement are unchanged.

Physical SRAM allocation is nine 1,024×16 macros plus twenty-one 128×16 macros: **190,464 bits, or 23.25 KiB**. Relative to prefetch8, the candidate adds one 1,024×16 macro, sixteen raw lanes (720 declared lane-state bits plus their arithmetic), 389 snapshot bits and modest bank/row-index control. The 789 W burst data/address bits and other controls also remain part of the design. Actual synthesized area and power must determine whether this exchange fits the target.

The independent testbench checks each X macro write using logical-row integer division/modulo, not the RTL's counters. Every complete task must cover all nine low-bank identities, 160 valid cross-bank-8 word transfers, and all 32 ignored dummy high halves. It retains the frozen direct 64-term accumulator and RNE/output golden, every W commit and slot generation, 99 hardware R factors, 256 C/bias/shift entries, 176 result snapshots and 1,584 R reads. Full-range synthetic, stall, error, reset and four-state write-Q-poison tests are run in addition to all 12 frozen real layer tasks.

The measured private window is **9,355 cycles = 2,152 load/wait + 35 factor/cache commit + 272 metadata read + 6,320 compute + 576 final tile drain**, versus prefetch8's 9,931. The compute counter includes 160 cycles waiting for the 36-word snapshots, so the output bottleneck is not hidden. Every fast task performs 512 W burst writes; 3,088 W input words and 224 metadata writes overlap DOT. All 12 real and ten synthetic tasks have this same no-stall count.

Three simulator seeds passed, each with 33 successful full tasks, seven interrupted tasks, two expected error completions and 857,952 pre-RNE checks including valid prefixes before abort/error. A separate four-state write-Q-poison protocol regression passed with 12 successful tasks, the same reset/error cases and 325,728 checks. The unique real coverage is 12 layers of validation sample 9, which is generated silence: 304,128 output elements. This is not an official 600-input evaluation. A focused additional test holds output backpressure across a concurrent metadata fault before draining and performing a full fresh reload.

Cycle counts, result identities and verification limits are recorded in `VALIDATION.json`. These are private-core measurements, not complete loader/CPU/SystemBus throughput. Numeric calibration and codec formats are unchanged, and this prototype does not replace the frozen production candidate without full-system and PPA evidence.
