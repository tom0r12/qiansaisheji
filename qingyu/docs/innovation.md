# 并行度与数据复用的同条件对照实验

本作品采用同一输入向多个乘累加通道广播、每通道独立权重 SRAM 分银行、
每个权重块在 99 行输入之间复用的架构。将并行通道数参数化为 1 和 4，
在相同冻结数值配置、相同真实验证输入和相同 RTL 控制方法下测量周期，
作为架构选择的量化依据。该技术属于本作品的设计和优化内容，不宣称首次提出。

**固定条件**

- 数据来自指定 KWT-1 权重和 Speech Commands V2 的冻结验证向量第 11 层。
  两种硬件均使用同一个 `integer_case.npz`，输入为 99×64、权重为 64×256，
  各完成相同的 1,622,016 次乘累加和 25,344 个输出。
- 使用同一份已在训练数据上冻结的输入尺度、逐输出通道权重尺度、偏置和移位。
  仅依据 LANES 重新排列文件；不重新量化、不重新校准、不改变累加顺序。
- 输入/权重为 INT16，累加为 48 位，输出为 INT32；舍入和饱和规则一致。
- 两种设计均使用相同的功能仿真时钟、同步行为 SRAM 和 ICB 主机测试流程。
  测试时钟名义为 150 MHz，1ps 仿真精度下周期量化为 6666ps；这不是 150 MHz
  静态时序通过证据。周期比不依赖把该时钟换算为绝对频率。
- 两种配置分别编译为独立原生仿真程序，使用不同构建目录，未改动生产 RTL、
  生产仿真脚本、默认缓存或正式数据文件。

**实测结果**

| 指标 | 单路基线 LANES=1 | 四路设计 LANES=4 |
|---|---:|---:|
| 输出通道块数量 | 256 | 64 |
| 检查的输出数 | 25,344，全部匹配 | 25,344，全部匹配 |
| 各块 COMPUTE_CYCLES 累计 | 3,296,768 | 844,736 |
| 测试主机 MMIO 窗口周期 | 3,498,880 | 1,044,864 |
| 总线请求总数 | 1,686,883 | 459,875 |
| 状态轮询读取数 | 1,648,640 | 422,400 |
| 写请求总数 | 12,386 | 12,002 |

四路设计的内部计算窗口周期相对单路缩短，周期比为 **3.90272**；
测试主机 MMIO 窗口的周期比为 **3.34865**。两种布局还使用完全相同的整矩阵
期望输出文件校验值，确认对照计算目标一致。

内部计算计数包含参数元数据读取、行初始化、同步 SRAM 读取、乘累加和输出块
存储，不能解释为纯乘法次数。四路同时更新四个通道的部分和，但输出结果仍经
共享写口序列化，并存在控制和初始化开销，因此实测周期比未达到整数 4。

MMIO 窗口从本任务第一笔输入写请求被接收起，到最后一笔输出读响应被主机
接收结束。其数据装载、等待和读回均由测试平台主机发起。请求总数包含窗口前
的 ID、复位和层号操作；轮询请求数随任务计算时长变化。**这个窗口没有执行
E203 的指令、共享 SRAM 搬运和最终结果写回，不能作为赛题端到端吞吐量。**

**复现与适用范围**

从项目根目录运行：

```powershell
python scripts/run_parallelism_study.py
```

若隔离构建目录与源文件校验值未改变，可用 `--skip-build` 复跑。
原生工具链沿用 `run_soc_verilator.py` 已配置的本地工具，不联网下载。
报告为 `reports/parallelism_study.json`，逐配置日志为
`reports/parallelism_study_l1_run.log` 和 `reports/parallelism_study_l4_run.log`。
临时测试平台、重排后的向量和两个构建目录位于 `build/parallelism_study/`。

本实验覆盖一层的一条冻结验证输入，用于功能一致和架构周期对比。它没有测量
单路和四路的面积、动态功耗或单任务能耗，也不能证明全数据集、完整 E203 系统
或官方统一评测条件下具有相同倍数的收益。正式创新报告应把本实验与现有 SoC
联调、指定工艺库综合及后续能耗评测并列呈现，不拼接不同配置的最优指标。
