# E203 整机任务性能测量

本流程直接运行 E203 固件与现有 ICB 接口。加速器 RTL、驱动算法和已完成时序优化的网表均未修改。性能测试使用独立固件 `sw/soc_perf_main.c` 和测试台 `tb/tb_qingyu_soc_performance.sv`。

## 计时口径

测试台只在复位前预装程序和位于共享 SRAM 上半区的源数据。实际输入、权重、偏置、移位参数缓冲区开始时为空。E203 通过真实 ICB 读写，将 47,744 字节复制到实际任务缓冲区，然后调用现有驱动。

- 起点：第一笔源输入读请求出现的时钟沿，包含该请求后续等待。
- 终点：25,344 个不同输出字全部写回共享 SRAM，最后一个写响应握手完成。
- 包含：CPU 装载、参数检查、加速器软件复位、调度、轮询、输入与参数送入加速器、总线等待、全部结果写回。
- 不包含：此前的上电复位、启动、程序下载，以及外部主机把源数据传到暂存区的时间。
- 每层独立启动一次仿真，重置 CPU 和加速器，禁止复用上层任务数据。

源暂存区与目标缓冲区共用现有功能 SRAM。它是明确的 **CPU 搬运工程模型**，不是组委会外部装载器的实测替代。共享 SRAM 当前一周期响应；真实宏封装或平台仲裁改变后需要重新测量。

`cycles` 是完整上述窗口；`load_cycles` 是 CPU 初始装载阶段；`live_cycles` 是首次读取实际参数到最后结果写回，便于与“共享 SRAM 已有任务数据”的接口边界比较。`start_to_live + live_cycles = cycles`。`accel_busy_cycles` 为计算忙周期，可能与 CPU 轮询重叠，不能与其它阶段直接相加。

`cmd_wait` / `rsp_wait` 只统计共享 SRAM 端口的 ready/valid 阻塞周期；`fio_cmd_wait` / `fio_rsp_wait` 对应外设总线端口。这些值为零也不代表总线零开销：请求/响应延迟、CPU 执行及上游仲裁均包含在完整时间窗口内。

每次运行必须同时满足：所有输入/参数装载数量正确、全部输出地址唯一且为完整字写、结果逐元素正确。仅出现计时标记不足以判定通过。

## 本机运行

在工程根目录使用带 NumPy 的 Python：

```text
python scripts/run_soc_performance.py --layers 0,11
python scripts/run_soc_performance.py --layers all --skip-build
```

结果在带时间戳的 `reports/soc_performance_*/summary.json`，保留源文件、固件、向量哈希和各层完整日志。仿真器运行耗费的电脑秒数不能作为芯片耗时。

150 MHz 条件下，耗时 = 周期数 / 150,000,000；串行任务吞吐量 = 150,000,000 / 周期数；每任务 MAC 数为 99×64×256。该吞吐量表示无任务间重叠时的稳态计算口径，未计任务间额外重启开销。最终能否按 150 MHz 宣称性能，仍取决于完整 SoC 时序和平台接口约束。

## 服务器 VCS

本机生成包：

```text
python scripts/run_soc_performance.py --layers all --package
```

上传工作区下的 `output/eda/qingyu_soc_performance.zip`（位于 `qingyu` 目录外）到服务器桌面，解压后运行 `sh ~/Desktop/qingyu_soc_performance/run.sh`。固件已编译，服务器无需安装 RISC-V GCC。包内没有工艺库。控制台每层仅打印计时摘要与输出校验结果，完整日志存入独立 `run_*` 目录。12 层使用项目冻结的验证向量，不能标成官方 12 个评测任务。

## 活动数据和整机功耗

测试台提供可选 `+ACTIVITY=/完整路径/task.vcd`，在上述起点 `$dumpon`、终点 `$dumpoff`，作用域为整个 `fixture.dut`。默认性能运行不生成大波形；服务器可用 `QINGYU_ACTIVITY_LAYER=layer00 sh .../run.sh` 只导出指定一层。当前属于 RTL 活动采集入口，需在 VCS 上确认实际导出及信号覆盖，不能直接作为已完成的门级功耗评测。

正式功耗工作尚缺完整 SoC 的同版本综合网表和配套映射，尤其是共享 512 KiB SRAM、E203 ITCM/DTCM 与完整外设，而不是仅已有的 9 个加速器内部宏。标准单元和 SRAM `.db` 已有部分工况，但 SRAM 功耗属性警告、操作模式、未标注信号和时钟覆盖仍需审查。

后续以冻结整机网表重新采集或可靠映射同一任务窗口活动，核对库工况/单位、宏数量、时钟、复位和活动覆盖后，再计算平均功耗以及单任务能耗 `E = P_avg × T_window`。禁止用加速器面积、默认翻转率或加速器单块功耗代替完整 SoC 功耗；未覆盖逻辑和 SRAM 不得按零功耗处理。
