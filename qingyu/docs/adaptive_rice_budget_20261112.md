# 自描述 adaptive Rice32：完整无损码流与预算复核

日期：2026-11-12。**建议暂不实现这两种新格式的 RTL。** 原行差分加自适应 k 在验证集的 `2I+O` 理想服务量仅平均减少 187.181 拍（1.366%）；排除生成静音记录后仅减少 53.788 拍（0.389%）。固定二维预测整体更差。收益不足以据此宣称冷装载完整窗口达标，也不足以证明新增 k 选择硬件值得其面积、关键路径和验证成本。

本研究仅新增 `scripts/analyze_adaptive_rice_budget.py`、本说明与 `build/adaptive_rice_budget_20261112/`。所有现有 RTL、数值配置、原码流和既有结果保持不变。主结果 `full/result.json` 的 `passed` 只表示下述无损性、源身份和计数检查通过，不是吞吐/面积/能耗验收。

## 在读数据之前固定的格式

预注册文件为 `build/adaptive_rice_budget_20261112/full/preregistration.json`。三种格式同时固定，不从训练或验证数据拟合参数，也没有在看到中间结果后修改预测器或块选择规则。

| 格式 | X / Y 预测 | W 预测 | Rice k |
| --- | --- | --- | --- |
| global Rice32 基线 | 原逐行模 256 差分，X 行宽 64，Y 行宽 16 | 无 | 原冻结 X=2、W=5、Y=3 |
| adaptive Rice32 | 同基线 | 无 | 每块自描述 k=0…7 |
| adaptive + gradient | 固定因果二维预测 | 无 | 每块自描述 k=0…7 |

每块至多 32 个字节；有符号字节采用原 signed8 zigzag。设块有 `n` 个符号，`u_i` 为 zigzag 值：

```
RicePayload(k) = Σ_i ((u_i >> k) + 1 + k)
Raw           = 1 selector bit + 8n payload bits
AdaptiveRice  = 1 selector bit + 3 k bits + RicePayload(k)
```

在八个 k 中选 payload 最短者，同分取较小 k。加上三个 k 位后，若不严格短于 raw，使用 raw。raw 块只发 `1 + n bytes`，不浪费三个 k 位；Rice 块发 `0 + k[2:0] + unary/remainder`。基线使用原固定 k，因此只有一个 selector 位。没有逐块字节/字对齐，仅每条完整流尾部补到 32 bit；最后不足 32 个符号的块使用实际 `n`。

二维候选的预测严格因果：首行预测 0；后续行第 0 列预测上方字节；其余列预测 `(left + above - upperleft) mod 256`，残差为 `(current - predictor) mod 256`。解码只依赖已恢复的本行左邻和前一行，没有预先计算未来输出。每条 X/W/Y 流重置预测 epoch。没有权重、矩阵输出或逐层特定内容放入 ROM。

## 冷开销与容量一项不少

- X 为一条 `99×64` 流；W 为八条 `64×32` 列组流；Y 为十六条 `99×16` tile 流。第 100 行补零仍由本地 adapter 生成，不传输。
- 输入 `I = 202 + ceil(Xbits/32) + Σ ceil(WgroupBits/32)`，其中 202 包含原 10 个格式/长度头词、128 个 INT16 bias 打包词和 64 个 shift 打包词。
- 输出实际写操作 `O = 18 + Σ ceil(YtileBits/32)`。18 包含初始 marker invalidate、16 个长度词和最终 magic 写入；静态头部只分配 17 词。不能沿用旧预算中未加 invalidate 的 17 次写入。
- 仍为每个输出 tile 预留 398 词，总输出分配 6385 词。未使用 slot 尾部不写入，也不计为实际总线流量。每条流最后一词的零 padding 已计入。
- raw escape 保证所有候选的最大 payload 不超过原上限：X 50886 bit，W 每组 16448 bit，Y 每 tile 12722 bit；新格式不需要扩大现有 slot，但实际接入必须使用不同 format/version。
- 每个任务仍真实装载所有 W。没有跨任务权重复用，也没有删除参数或只计输出。

基线每任务已有 198+512+800=1510 个块 selector 位。自适应版本另外产生平均 X 594、W 1495、Y 2399.978 个 k 位（验证集）；这些约 4488.978 bit 的块头开销已经纳入表中，没有当作免费元数据。

## 数据与检查

原 training 和 validation 各 256 个样本 × 12 层，即每个 split 3072 个完整任务。使用冻结 `x8_w8_y8_h0` 数值配置和原张量身份哈希，不重新标定或更改精度。两 split 中相同的生成静音声学内容不能视为相互独立的真实声音；本研究不是官方 600 样本评测。

三格式总计完成 **460800 条实际位流 encode/decode、885915648 个矩阵元素的精确恢复**。每个任务的 25 条流都实际运行，包括每任务重新编码/解码八条 W 流；不是只用熵或长度估计代替位流。原 native C++ 写码器和独立读码器传递实际序列化字节；解码检查 unary 范围、canonical raw/k 选择、精确结束位置和末字节零 padding。恢复残差后独立逆预测，逐元素核对完整 X/W/Y。

每条流的位数和 k/header 计数另与 NumPy 实现对照；480 个 all-byte、随机、全零、极值、所有 k、短尾用例还与纯 Python 逐 bit 写码器对照，320 个截断码流被拒绝。完整基线验证集的每任务 X/W/Y 各流位数、I 以及 O（旧结果加一次 invalidate）与冻结 tiled 研究全部一致。脚本/配置/数据/辅助源哈希在运行结束重新核对。

- 验证集 264 个任务对应生成静音，adaptive 的 `2I+O` 平均少 1606 拍。
- 其余 2808 个任务平均仅少 53.788 拍，输入反而多 5.974 词；平均 `2I+O` 从 13829.807 变为 13776.019。
- 按任务配对，1806 个变好、19 个相同、1247 个变差；配对节省中位数 23 拍，最大额外开销 153 拍。两格式各自中位数为 global 13761、adaptive 13765；不能以总均值概括所有音频。

## 完整 strict 窗口不能用服务下界替代

若真实 loader 必须先完整写入压缩输入，随后 CPU/engine 才 START：

```
Cstrict = Cloader + Cengine + 未纳入两者的真实调度开销
Cloader >= I       （仅假设每拍一个成功写入且没有额外生成/装载开销）
Cengine >= 实际依赖、计算、读写、codec、fill/drain共同约束
```

`2I+O` 只把所有输入写、输入读、输出写加总，不能自动把计算及编码与这些事务完美重叠。也不能把串行 `Cloader+Cengine` 换成 `max(Cloader,Cengine)`。输入包如何由真实平台 loader 提供、开始点到底在哪里仍为 OPEN；不把当前 reset 前预装算入已测窗口，也不据未明确规则认定现有工程结果就是官方分数。

冻结 dual+prefetch8 的已有实测 bare-engine 时间，加上最乐观每输入词一拍的串行初始 loader，可形成以下**有条件预算，不是已测完整窗口**：

| 原 fixed-codec 样本 | Cengine+I 最小 / 均值 / 最大 |
| --- | --- |
| 009 生成静音 | 14542 / 14619.583 / 14663 |
| 000 | 15174 / 15377.917 / 15551 |
| 202 高流量 | 16466 / 16734.667 / 17025 |

不得把本表原 fixed-codec 的 engine 周期直接套给 adaptive 新格式。新格式可能改变解码等待和背压，新增选择状态也可能增加延迟；必须实现后实测。当前 adaptive 的约 187 拍平均理想流量改善无法作为这些缺口已解决的证据。继续核和调度优化更有依据。

## 若以后重启 RTL，必须支付的硬件成本

编码器先收完整 32-symbol 块才能作 canonical raw/k 决策。可以保留原两个 32B 块缓冲，同时在填入时累计八个候选 cost。最简单精确实现的单项最大 cost 为 `32×256=8192`，需 14 bit；八项为 112 bit。由于只需知道是否优于 raw，可证明安全地饱和到 256，用八个 9-bit 累计器共 72 bit，但必须单独验证尾 16-symbol 块阈值及同分规则。

原编码器只有一个 16-bit cost 寄存器；新的八项代替它，还要给两个等待块各保存 3-bit k、decoder 保存当前块 k，并实现八路比较选优。四符号每拍需要八种常量移位/四项求和、累计和比较，完整块最后拍的选择树是新的关键路径候选。可以流水但要真实计启动、阻塞和 flush；不能把原 fixed-codec service 周期当作已经证明的新值。raw 已在整块决策后确定，Rice 全块总长才有上界，不能先截断长 unary 来假装固定工作量。

二维预测可复用 encoder 的 16B 与 decoder 的 64B 一行历史，但需要前一原始/恢复 left、upperleft 等额外状态（典型各 8 bit），以及四 lane 因果重建的串联或前缀加法网络；历史四字节读写端口及同拍旧值保持必须验证。START 用首行 epoch 隔离旧数据，不依赖清未初始化 RAM。这些是结构预算，没有综合/STA/布局面积或能耗结果。

2 symbols/cycle 的单独输入解码下界为 11360 拍、输出编码为 12672 拍；4 symbols/cycle 分别为 5680 和 6336 拍。这只是符号服务量，未加全块选择、接口握手、码流字带宽、部分字 flush 或重排；较小码流没有减少固定的 22720 个输入字节和 25344 个输出字节。
