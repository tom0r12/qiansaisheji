更新：2026-11-12。当前远程服务器仅用于验证已上传的 INT8 系统总线包；本页不保存账号、密码或连接凭据。

- 八行与九行紧凑私有 SRAM 验证包已分别上传，归档 SHA-256 为 `a66b63e7fad40e229f7cceb9c8c14377991bbe1b0b7bb50a417e17c0bd436033` 和 `81377bb70f72f2d9ad3fe3708e4a7ceb78a5b468b3eeab96133357265ef9f772`。
- 在服务器桌面的包目录运行 `sh qic8 --mode validate` 和 `sh qic9 --mode validate`，两个归档均显示 `OK`，随后包校验通过。
- 服务器存在 `SRAM_Lib_2025` 的 RAMSP128X16、RAMSP1024X16、RAMSP4096X16 模型文件，已记录实际文件哈希。

`validate` 只检查归档完整性和包内文件清单，不运行仿真、宏模型、综合或功耗分析。厂家宏身份审核清单仍待建立，因此目前**没有**厂家宏仿真、综合面积、Formality、150 MHz STA 或整机功耗结果。

## 后续执行顺序

1. 根据服务器提供的 SRAM_Lib_2025 来源核验三个模型文件，建立带来源说明和 SHA-256 的模型身份清单。
2. 对八行和九行候选分别运行 `--mode macro`，先短任务检查，再运行包内完整 72 任务。用于功耗的宏仿真需要启用活动轨迹。
3. 按包内 `templates/` 示例建立服务器本地配置：指定 SCC40NLL 标准单元库、库与 SRAM 宏面积单位、真实工艺角、互连估计和全 SoC SDC。配置必须约束完整数字 SoC 的 150 MHz 主时钟、32.768 kHz 常开时钟、生成时钟和 I/O。
4. 对同一候选依次运行 `synth`、`formal` 和 `sta`，检查增量面积分类、等价结果及完整约束下的时序。
5. 从同一宏仿真的 VCD 截取任务活动窗口，转换并审核 SAIF 覆盖，再对同一个已映射网表运行 `power`。结果必须包含 CPU、总线、加速器、全部 SRAM 和固定数字外设的活动与功耗。

包内运行入口和参数见 [`SERVER_README.md`](../experiments/integration/int8soc_server/SERVER_README.md)。所有阶段都必须使用同一个包和与之哈希绑定的结果；包校验通过不等于远程 EDA 通过。

## 测量窗口

当前包记录的工程窗口从第一笔 CPU 参数配置写接受，到最后结果 marker 写响应 ACK；初始 source preload 和此前启动时间不在窗口内。题面官方 loader 的精确起点仍需按正式平台接入测量。不得将预装窗口的吞吐或功耗说成完整官方结果。
